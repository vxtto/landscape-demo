SIGNAL A

协议开始占据版面

MCP、A2A、AG-UI、A2UI 等项目让工具、agent、界面和上下文之间出现了更明确的连接层。标准化的不是“智能”，而是协作接口。

SIGNAL B

推理栈继续分化

推理引擎、KV cache、编译器、部署和调度不再适合被压成一个方块。Agent 的长链路与并发负载正在把系统问题重新放大。

SIGNAL C

README 开始被机器执行

Awesome 项目从收藏清单变成 agent 的技能索引、工具入口和运维手册。24 个入选项目中，19 个具备直接 agent-consumable 入口。

03 · InclusionAI

把开放做成一套
可以进入、可以验证、可以继续贡献的技术栈。

InclusionAI 的观察价值不在于仓库数量本身。更重要的是，它尝试把模型、训练系统与 agent 运行时连接起来，让没有大规模训练资源的开发者也能从环境、工具、评测或运行时进入。

Participation surfaces

开放技术栈提供了不同成本的贡献入口

模型研究者可以改训练与评测；系统研究者可以优化并行、环境和运行时；应用开发者可以贡献工具、任务和可复现实验。共同点不是“所有东西都在一个 org”，而是接口与结果能够被公开验证。

AReaL 的主仓库位于 areal-project/AReaL，这里按技术栈关系呈现，不把它计入 inclusionAI org 的 58 个仓库。

给演讲者的讲法 · 约 5 分钟
依次点模型、训练、运行时三层，每层只举一两个项目和一种可贡献内容。不要把 58 个仓库念成成绩单，也不要说它们全部属于同一个 GitHub org。重点是“参与面”：即使不能训练基础模型，也能改环境、任务、评测和 runtime，并通过公开结果进入协作。
04 · License and openness

开放模型时代，
一份许可证只能说明一部分事实。

软件许可证回答权利、义务和责任边界；模型开放还需要回答权重、架构、训练代码、数据说明、评测与文档究竟提供到了什么程度。这两类问题必须分开检查。

05 · Community over code

Community >>> Code，
不是一句温情口号。

它描述了一套把陌生贡献变成长期信任的机制。入口要能被找到，讨论要经得起回看，权限要跟着可见贡献增长。代码、模型和 agent 都会变；这套机制决定变化能否被更多人接住。

DISCOVERABLE

贡献表面要清楚

Good first issue、公开 roadmap、模型卡、数据说明、评测任务和工具接口，让潜在贡献者知道“从哪里开始”。

REVIEWABLE

决定要留下理由

公开 proposal、邮件列表、issue / PR 审查与可复现实验，让技术选择不依赖某个公司的内部上下文。

EARNED

权限跟随贡献

从使用者到 contributor、committer 和 member，权限来自持续、可见、可被社区检验的工作。

老规矩要保留的，是透明入口、公开过程和渐进式信任；需要扩大的，是它们覆盖的对象——代码之外还有模型、数据、工具、评测与治理。

给演讲者的讲法 · 约 3 分钟
逐个点击贡献路径，但不要把结尾讲成价值观清单。举一个具体动作：一个模型发布如果能被社区继续训练，需要的不只是下载按钮，还要有材料、复现实验、公开问题和变更过程。最后停在三个资源入口，把“听完”变成“可以开始参与”。
